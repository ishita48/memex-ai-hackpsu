WHAT IS THE API PRODUCT?
================================================================================

Memex AI is now a PLATFORM, not just a dashboard. Any external tool — VS Code
extensions, Python scripts, CI/CD pipelines, Slack bots, CLI tools, other apps —
can call your Memex AI backend using an API key to:

  1. INGEST data (store logs/errors/events into the memory engine)
  2. QUERY data (search memory and get AI reasoning)
  3. Manage incidents, feedback, and alerts

The dashboard still works the same. The API is an additional way to access
the same backend. Everything goes to the same Supabase database.

HOW API AUTH WORKS
================================================================================

The auth logic lives in lib/api-auth.ts:

  1. Request comes in to /api/ingest or /api/query
  2. validateApiKey(req) checks:
     a. Is this a same-origin request (dashboard)? → ALLOW (no key needed)
     b. Does the request have x-api-key header? → Check against MEMEX_API_KEY env var
     c. Also accepts Authorization: Bearer <key> format
  3. If no key or wrong key → returns 401/403 error
  4. If valid → returns { userId } and the route continues normally

Dashboard users never see auth. It's invisible to them.
External apps MUST send the key.

API ENDPOINTS AVAILABLE
================================================================================

All endpoints accept JSON. External requests need x-api-key header.

POST /api/ingest
  Purpose: Store a new log/error/event
  Auth: Required for external, auto-bypass for dashboard
  Body: {
    "type": "error",              // "error" | "network" | "api"
    "source": "auth-service",     // where it came from
    "content": "NullPointerException at AuthController.java:142...",
    "metadata": {
      "severity": "critical",     // "critical" | "high" | "medium" | "low"
      "service": "auth-service",
      "title": "NullPointerException in AuthController",
      "commit": "a3f9b2c"         // optional
    }
  }
  Response: {
    "success": true,
    "id": "uuid",
    "incident_id": "uuid",
    "is_new_incident": false,     // true = new incident, false = clustered
    "alert_triggered": true,      // true if critical/high severity
    "message": "Memory added to existing incident cluster"
  }

POST /api/query
  Purpose: Search memory with AI reasoning
  Auth: Required for external, auto-bypass for dashboard
  Body: {
    "question": "null pointer auth",   // natural language
    "mode": "sentry"                   // "sentry" | "comcast" | "base44"
  }
  Response: {
    "results": [ array of matching memories with similarity scores ],
    "reasoning": "**Root Cause:** ...\n**Impact:** ...\n**Fix:** ...\n**Pattern:** ...",
    "pattern": "2 related incidents detected spanning 3 days"  // or null
  }

GET /api/incidents?mode=sentry&status=open
  Purpose: List grouped incidents
  Auth: Not yet protected (add validateApiKey if needed)

GET /api/incidents?id=<uuid>
  Purpose: Get all memories for a specific incident

PATCH /api/incidents
  Purpose: Update incident status
  Body: { "id": "uuid", "status": "resolved" }

POST /api/feedback
  Purpose: Rate a search result
  Body: { "memory_id": "uuid", "action": "helpful" }  // or "not_helpful" or "resolve"

GET /api/alerts?unread=true
  Purpose: List alerts

PATCH /api/alerts
  Purpose: Acknowledge an alert
  Body: { "id": "alert-uuid" }

HOW TO USE THE API — EXAMPLES
================================================================================

--- CURL (terminal / command line) ---

Ingest a new error:
  curl -X POST http://localhost:3000/api/ingest \
    -H "Content-Type: application/json" \
    -H "x-api-key: memex_sk_a7b3f9d2e1c4k8m5n0p6q9r2s7t4u1" \
    -d '{
      "type": "error",
      "source": "payment-service",
      "content": "Timeout on Stripe webhook after 30s",
      "metadata": {"severity": "high", "title": "Stripe webhook timeout"}
    }'

Search memory:
  curl -X POST http://localhost:3000/api/query \
    -H "Content-Type: application/json" \
    -H "x-api-key: memex_sk_a7b3f9d2e1c4k8m5n0p6q9r2s7t4u1" \
    -d '{"question": "stripe timeout", "mode": "sentry"}'

Browse all (empty question):
  curl -X POST http://localhost:3000/api/query \
    -H "Content-Type: application/json" \
    -H "x-api-key: memex_sk_a7b3f9d2e1c4k8m5n0p6q9r2s7t4u1" \
    -d '{"question": "", "mode": "sentry"}'

--- PYTHON ---

  import requests

  MEMEX_URL = "http://localhost:3000"
  MEMEX_KEY = "memex_sk_a7b3f9d2e1c4k8m5n0p6q9r2s7t4u1"
  HEADERS = {"Content-Type": "application/json", "x-api-key": MEMEX_KEY}

  # Ingest
  res = requests.post(f"{MEMEX_URL}/api/ingest", json={
      "type": "error",
      "source": "my-python-app",
      "content": "ValueError: invalid literal for int() with base 10: 'abc'",
      "metadata": {"severity": "medium", "title": "ValueError in parser"}
  }, headers=HEADERS)
  print(res.json())
  # → {"success": true, "incident_id": "...", "is_new_incident": true, ...}

  # Query
  res = requests.post(f"{MEMEX_URL}/api/query", json={
      "question": "ValueError parser",
      "mode": "sentry"
  }, headers=HEADERS)
  data = res.json()
  print(data["reasoning"])
  # → "**Root Cause:** ..."

--- GITHUB ACTIONS (auto-report CI failures) ---

  # .github/workflows/memex.yml
  name: CI
  on: push
  jobs:
    build:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4
        - run: npm test
        - name: Report failure to Memex AI
          if: failure()
          env:
            MEMEX_URL: ${{ secrets.MEMEX_URL }}
            MEMEX_API_KEY: ${{ secrets.MEMEX_API_KEY }}
          run: |
            curl -X POST $MEMEX_URL/api/ingest \
              -H "Content-Type: application/json" \
              -H "x-api-key: $MEMEX_API_KEY" \
              -d "{
                \"type\": \"error\",
                \"source\": \"github-actions\",
                \"content\": \"CI failed on ${{ github.ref }} - ${{ github.event.head_commit.message }}\",
                \"metadata\": {
                  \"severity\": \"high\",
                  \"commit\": \"${{ github.sha }}\",
                  \"repo\": \"${{ github.repository }}\",
                  \"title\": \"CI failure on ${{ github.ref }}\"
                }
              }"

--- SENTRY WEBHOOK (auto-ingest real Sentry errors) ---

  // Create a webhook endpoint in your app or a separate service:
  app.post('/webhook/sentry', async (req, res) => {
    const event = req.body;
    await fetch(MEMEX_URL + '/api/ingest', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'x-api-key': MEMEX_API_KEY,
      },
      body: JSON.stringify({
        type: 'error',
        source: event.project?.name || 'sentry',
        content: event.message || event.title,
        metadata: {
          severity: event.level === 'fatal' ? 'critical' : event.level,
          title: event.title,
          url: event.url,
          ingested_via: 'sentry-webhook'
        },
      }),
    });
    res.sendStatus(200);
  });

  // Then in Sentry → Settings → Webhooks → add your URL

WHAT'S NOT YET PROTECTED
================================================================================

Currently only /api/ingest and /api/query have API key validation.
These routes do NOT require a key yet:
  - GET/PATCH /api/incidents
  - POST /api/feedback
  - GET/PATCH /api/alerts

To protect them, add the same 2 lines at the top of each route:
  import { validateApiKey } from "@/lib/api-auth";
  // inside the handler:
  const auth = await validateApiKey(req);
  if (auth.error) return auth.error;
